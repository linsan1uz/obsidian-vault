## 1. 从一个坏例子开始（10 分钟）

假设你写了个点单页，三种饮品，每个都要"图标 + 名字 + 价格 + 加减按钮"：

```arkts
// ❌ 反面教材：同样的结构手写三遍，改一个样式要改三处
Column() {
  Row() { Text('🧋'); Text('拿铁 ￥15'); Button('-'); Text('0'); Button('+') }
  Row() { Text('☕'); Text('摩卡 ￥18'); Button('-'); Text('0'); Button('+') }
  Row() { Text('🍵'); Text('红茶 ￥12'); Button('-'); Text('0'); Button('+') }
}
```

三个 Row 结构完全一样，只有数据不同——这就是**必须拆组件**的信号。拆完长这样：

```arkts
DrinkRow({ name: '拿铁', price: 15, count: $countLatte })
DrinkRow({ name: '摩卡', price: 18, count: $countMocha })
DrinkRow({ name: '红茶', price: 12, count: $countTea })
```

写一遍模板，数据各喂各的。改样式只改一处，十个商品也轻松扩。

## 2. 拆组件三步法：切 → 抽 → 连（15 分钟）

**第一步：切**——盯着设计稿找两类东西：
- **重复结构**（如上面的商品行）→ 必拆；
- **独立职责区**（导航栏、底部合计栏）→ 建议拆。

**第二步：抽**——确定组件的"接口"。组件 = 零件，零件要有插口：

```arkts
@Component
struct DrinkRow {
  name: string = ''               // ① 普通成员：不变化的数据（名字、价格）
  price: number = 0
  @Link count: number             // ② 状态成员：需要和父组件联动的数据

  build() { ... }                 // ③ 用 this.name / this.count 渲染
}
```

插口分两类：**纯展示数据**（父给什么显示什么）和**联动数据**（父子要一起改）。选哪个装饰器，是下一步。

**第三步：连**——决定每条数据用哪条通道通信。这是今天的核心，下面细讲。

---

## 3. 四条通道：一张地图（15 分钟）

| 通道 | 方向 | 心智比喻 | 判断口诀 |
|------|------|---------|---------|
| 普通成员 | 父 → 子（展示） | 印在说明书上的参数 | 不用改，就不用装饰器 |
| `@Prop` | 父 → 子（拷贝） | 拍张照片带回家改 | 要本地改，但**不想**影响父 |
| `@Link` | 父 ↔ 子（同步） | 共用一本账本 | 要改，而且**就要**影响父 |
| 回调函数 | 子 → 父（事件） | 按门铃，家长来开门 | "发生了事"，父决定怎么办 |

先记判断口诀，细节往后看。核心直觉：**数据向下流，事件向上流**（单向数据流）。

### 普通成员：默认选择

```arkts
@Component
struct DrinkRow {
  name: string = ''        // 不需要子组件修改 → 不加任何装饰器
  ...
}
DrinkRow({ name: '拿铁' })
```

父数据变了它会跟着更新（单向同步），但子组件**自己改它不触发刷新**。所以它只配承担"不变的数据"。新手常见错误是给所有成员都套装饰器——**装饰器是有代价的（观察开销 + 语义约束），不需要就不加**。

### @Prop：复印件

```arkts
@Prop count: number = 0        // 可以有本地默认值
// 父：DrinkRow({ count: this.total })
```

- 子组件拿到的是**值的拷贝**：本地随便改，父组件毫不知情；
- 但父数据一变，拷贝被**整个覆盖**——你本地改的东西瞬间消失；
- 本地修改**会**刷新子组件自己的 UI（这是它强于普通成员的地方）。

典型场景：**草稿态**——表单编辑副本，点"保存"才通过回调交还父组件。

### @Link：账本

```arkts
@Link count: number             // 不能写本地默认值！
// 父：DrinkRow({ count: $countLatte })   ★ 必须带 $
```

- `$` 传递的是状态变量的**引用**，父子读写同一份数据，任何一边改，两边 UI 都刷新；
- 因为数据所有权在父组件，所以 **@Link 禁止本地初始化**（没有"自己的默认值"可言）；
- 共享引用意味着修改遵守 Day 5 的"第一层观察"规则（深层改动要 splice / 整体替换）。

典型场景：**直改父数据**——计数器、开关、内联编辑。

### 回调函数：门铃

```arkts
@Component
struct OrderBar {
  total: number = 0
  onClear: () => void = () => {}    // 函数当成员，空实现兜底

  build() {
    Button('清空').onClick(() => this.onClear())   // 子：只按门铃
  }
}
// 父
OrderBar({ total: this.total(), onClear: () => { /* 清空逻辑父组件自己写 */ } })
```

**@Link 还是回调？** 简单直改用 @Link 最省事；当"子组件的一个动作牵扯多份数据、或需要校验/日志"时，用回调把决策权收回父组件。判断标准：**希望子组件更傻更好复用 → 回调**。

## 4. 贯穿案例：奶茶点单页（30 分钟）

完整代码在 `OrderDemo-5.3flash.ets`，结构如下：

```
OrderDemo（页面 = 数据主人）
├── DrinkRow × 3        普通成员（name/price） + @Link（count → Stepper）
│    └── Stepper        @Link 双向的加减步进器（复用件）
└── OrderBar            普通成员（total） + 回调（onClear）
```

三个设计决策值得咀嚼：

1. **name/price 用普通成员**：展示数据，子组件不会改它们——不加装饰器；
2. **count 用 @Link**：加减就是改父组件的账，双向同步名正言顺；
3. **合计 total 用方法算，不存 @State**（Day 5 的"能算不存"）：

```arkts
total(): number {
  return this.countLatte * 15 + this.countMocha * 18 + this.countTea * 12
}
// build 里直接用：OrderBar({ total: this.total(), ... })
```

三个 count 变量有点重复感？真实项目会用对象数组 + @Observed/@ObjectLink 解决（Day 17）。现在先感受这个限制，才知道后面那些工具是为什么存在的。

**实验剧本**（跑起来照着做）：
1. 点任意 Stepper 的 +/-：行内数字变、底部合计**立刻**变——@Link 双向 + 派生合计；
2. 点"清空"：三个数全归零——回调上行使父组件重置数据，@Link 再同步下去；
3. 打开 Log 窗口：每次数量变化都有一行 `[Watch]` 日志——见下一节。

## 5. @Watch：刷新之外的事（15 分钟）

UI 跟随数据是框架的本分，**不需要** @Watch。它管的是"数据变了，我还要额外做点什么"：

```arkts
@Component
struct Stepper {
  @Link @Watch('onValueChanged') value: number

  onValueChanged() {
    console.log(`[Watch] 数量变为 ${this.value}`)     // 存盘 / 埋点 / 动画 / 触发请求
  }
  ...
}
```

规则：

1. 语法：`@Link @Watch('方法名')`，方法无参无返回值，值一变立即调用；
2. 只能挂在**状态装饰变量**上——普通成员的变化框架本来就看不见（Day 5"被观察"的延续）；
3. 回调里**别反向修改被监听的变量**，容易无限循环；
4. 派生数据（如合计）**不需要** @Watch——build 里方法调用每次刷新自动重算。@Watch 留给"必须做动作"的副作用。

## 6. 选型速查表（收藏贴墙）

| 需求 | 用什么 |
|------|--------|
| 子组件展示一份数据，永不修改 | 普通成员 |
| 子组件要本地编辑，但不应影响父 | @Prop（+ 保存时回调交还） |
| 子组件直接增删改父的数据 | @Link（`$` 绑定） |
| 子组件报告事件，父组件决策 | 回调函数 |
| 数据变了要存盘/打日志/开动画 | @Watch |
| 派生数据（合计、完成度） | build 里调方法，不存状态 |

---

## 7. 常见坑速查

| 现象 | 原因 |
|------|------|
| 传参给 @Link 编译报错 | 漏了 `$`：`Stepper({ value: $count })` |
| @Link 写了默认值报错 | @Link 禁止本地初始化，删掉 `= 0` |
| 子组件改了数据界面没反应 | 改的是普通成员（不触发刷新），换 @Prop/@Link |
| @Prop 本地改了又被弹回 | 父数据变化覆盖副本——特性；想保留就在变化时回调交还父组件 |
| 给所有成员都套 @State/@Prop | 装饰器按需用，纯展示数据用普通成员 |
| @Watch 不触发 | 挂在普通成员上，或修改没被观察（Day 5 第一层规则） |
| 一个文件两个 @Entry | 一个文件只能有一个页面入口 |
